**Розгортання Java-проєкту та базова обробка даних**
Курс «Кросплатформні засоби програмування», Національний університет «Львівська політехніка»,
кафедра електронних обчислювальних машин.
Виконав: Бичик Вадім, група КІ-304. Репозиторій: <https://github.com/dapii44/kzp-lab01-bychyk>

## 1. Тема, номер і варіант

- Предметна область: **спортивні тренування**.
- Номер варіанта: **2** (незмінний у всіх наступних роботах).
- Операційна система розробки: Ubuntu 24.04 (Linux), JDK 21 (OpenJDK 21.0.13). Windows і macOS
  перевіряються в GitHub Actions (матриця з трьох ОС).

## 2. Мета роботи

Пройти повний шлях від порожнього репозиторію до консольної програми, яку можна відтворено
зібрати й запустити на Windows, macOS та Ubuntu: структура репозиторію, Maven із Wrapper, JUnit 5,
статичний аналіз SpotBugs, виконуваний JAR із версією й номером збірки, GitHub Actions,
GitHub Issues і Pull Request. Досягнуто **рівня 3** (повний цикл).

## 3. Постановка задачі

Формат одного запису (UTF-8, поля через `;`, числа з крапкою):

```text
date:String; kind:String; minutes:int; distanceKm:double; calories:int
2026-09-01;Біг;45;7.50;520
```

Чотири показники варіанта 2:

1. кількість коректних записів;
2. сумарний час (хвилини);
3. сумарна дистанція (км);
4. найбільша витрата калорій.

Правила коректності: дата та вид не порожні; рівно 5 полів; `minutes`, `calories` — цілі `>= 0`;
`distanceKm` — скінченне число `>= 0` (нуль допустимий: йога, силове); має бути хоча б один
коректний запис. Хибний рядок не зупиняє програму: у звіті вказано номер рядка та причину.

## 4. Структура програми

```text
src/main/java/ua/lpnu/kzp/
├── Main.java            # точка входу, режими --help / --version, коди завершення
├── CliOptions.java      # розбір --help, --input, --output
├── TrainingStats.java   # читання → перевірка → перетворення → накопичення показників
├── ReportFormatter.java # один текст звіту для консолі й файла
├── FileReport.java      # читання/запис файлів через Path, Files, UTF-8
└── BuildInfo.java       # версія з version.properties (Maven resource filtering)
```

Потік даних: `data/input.csv → FileReport.readLines → TrainingStats.accept (рядок за рядком) →
ReportFormatter.format → консоль + out/report.txt`. Читання, обчислення й форматування розділені
на різні класи: у лабораторній роботі № 2 рядкове представлення буде замінено класом-сутністю без
зміни звіту.

## 5. Інфраструктура

| Елемент | Реалізація |
| --- | --- |
| Система збирання | Maven, `groupId=ua.lpnu.kzp`, `artifactId=lab01`, `version=1.0.0`, Java 21 (`maven.compiler.release`), UTF-8 |
| Wrapper | `mvnw`, `mvnw.cmd`, `.mvn/wrapper/maven-wrapper.properties` (Maven 3.9.11, Wrapper 3.3.4) — скрипти взято з офіційного репозиторію Apache `maven-wrapper` |
| Тести | JUnit Jupiter 5.12.2 (`scope=test`), maven-surefire-plugin 3.5.2 |
| Статичний аналіз | SpotBugs (`spotbugs-maven-plugin` 4.9.7.0), ціль `check`, фаза `verify` |
| Пакування | `maven-shade-plugin` 3.6.0, `Main-Class: ua.lpnu.kzp.Main` → виконуваний JAR |
| Версія | `1.0.0` у `pom.xml` та Git-тег `v1.0.0`; номер збірки — властивість `build.number` (`local` локально, `github.run_number` у CI) |
| CI | `.github/workflows/ci.yml`: матриця `ubuntu-latest`, `windows-latest`, `macos-latest`; JDK 21 Temurin; `mvnw verify`; перевірка `--version`; запуск JAR на контрольних даних; публікація JAR як артефакту |

Версію й номер збірки розділено навмисно: `--version` виводить `1.0.0+local` (локально) або
`1.0.0+42` (CI). За SemVer усе після `+` — метадані збірки; номер збірки не додається до
`<version>`, щоб кожен запуск CI не створював новий артефакт Maven, а тег `v1.0.0` відповідав POM.

Увага щодо життєвого циклу: у Maven фаза `package` виконується **перед** `verify`, тому JAR
створюється до аналізу SpotBugs, а команда `verify` включає компіляцію, тести, пакування й аналіз.

## 7. Приклади роботи

**Вхідні дані** (`data/input.csv`, 5 коректних рядків і 4 хибні, зокрема порожній рядок):

```text
2026-09-01;Біг;45;7.50;520
2026-09-03;Велосипед;90;28.40;780
2026-09-05;Плавання;60;2.00;450

2026-09-07;Йога;50;0.00;180
2026-09-09;Ходьба;70;5.60;300
2026-09-10;Біг;абв;5.00;300
2026-09-11;Силове;-30;0.00;250
2026-09-12;Біг;40;5.00
```

**Консольний вивід і файл `out/report.txt`** (однаковий текст):

```text
Звіт про тренування
Коректних записів: 5
Сумарний час: 315 хв
Сумарна дистанція: 43.50 км
Найбільша витрата калорій: 780 ккал
Помилок: 4
Рядок 4: порожній рядок
Рядок 7: поле minutes має помилковий формат
Рядок 8: від'ємне числове значення
Рядок 9: очікується 5 полів, отримано 4
```

Перевірка вручну: 45+90+60+50+70 = 315 хв; 7.5+28.4+2.0+0.0+5.6 = 43.5 км; максимум калорій 780.

**Режими:** `--help` друкує використання; `--version` → `1.0.0+local`; відсутній файл → код 2;
файл без коректних записів → код 1; невідомий аргумент → код 2 та довідка.

## 8. Тестування

Локальна перевірка (Ubuntu 24.04, JDK 21; тести виконано JUnit Platform Console, оскільки
Maven Central недоступний у середовищі розробки — повний `mvnw verify` підтверджує CI):

```text
javac --release 21 -Xlint:all -Werror ...      # без попереджень
JUnit Platform Console:  26 tests found, 26 successful, 0 failed
java -jar target/lab01-1.0.0.jar --version      # 1.0.0+local
```

SpotBugs у середовищі розробки не запускався (його не можна встановити без Maven Central);
код написано з урахуванням типових правил (копії колекцій, явне UTF-8, без `null`-розіменувань),
а фактичний результат аналізу підтверджує крок `verify` у CI.

нечислове значення в кожному числовому полі, NaN/Infinity, від'ємні значення й нуль як межа,
порожні дата й вид, пробіли навколо чисел, незмінність показників після хибного рядка,
українські символи, копія списку помилок, UTF-8-запис/читання, режими CLI, коди завершення,
еталонний звіт, формат версії.

## 10. Відповіді на контрольні питання

1. **Призначення `pom.xml`.** Це опис проєкту для Maven: координати артефакта, версія Java,
   кодування, залежності, плагіни й налаштування збірки. Maven не вгадує їх із назв каталогів.
2. **`test`, `verify`, `package`.** Це фази життєвого циклу; виклик пізнішої виконує всі
   попередні. `test` — компіляція й запуск тестів; `package` — додатково створення JAR;
   `verify` іде після `package` і виконує перевірки якості (тут SpotBugs `check`). Тому
   `verify` — найповніша команда.
3. **Maven Wrapper** дає однакову версію Maven (3.9.11) на будь-якому комп'ютері й у CI без
   глобальної установки: `mvnw`/`mvnw.cmd` завантажують потрібну версію під час першого запуску.
4. **Метод `main`** — точка входу: JVM викликає його на початку виконання й передає масив
   аргументів командного рядка.
5. **Примітивний тип і `String`.** Примітив (`int`, `double`) зберігає значення безпосередньо,
   не має методів і не може бути `null`; `String` — незмінний посилальний тип з методами.
6. **Середнє в `double`:** ділення двох `int` відкидає дробову частину (7/2 = 3), тому один
   операнд приводять до `double`: `(double) total / count`.
7. **`Integer.parseInt("abc")`** кидає `NumberFormatException`; її перехоплюють на рівні одного
   рядка, щоб інші рядки оброблялися далі.
8. **Мовчки пропускати рядок не можна:** показники виглядали б правильними, а користувач не
   знав би про втрату даних. Тому в звіті є номер рядка й причина.
9. **`split(";", -1)`** зберігає порожнє останнє поле: `"a;b;"` дає три елементи, останній —
   порожній рядок. Без `-1` порожні хвостові поля відкидаються й перевірка кількості полів
   пропустила б хибний рядок.
10. **`Path.of`** сам обирає роздільник шляху для поточної ОС, тоді як рядок `"data\\input.csv"`
    працює лише у Windows.
11. **Явне `UTF-8`:** стандартне кодування залежить від ОС (на Windows може бути Windows-1251
    або 1252), і кирилиця зіпсується.
12. **`%n` проти `\n`:** `%n` дає роздільник рядка поточної ОС (CRLF у Windows, LF в Unix),
    а `\n` завжди LF.
13. **Перевіряються:** порожній рядок; рівно 5 полів; непорожні дата й вид; `minutes` та
    `calories` — цілі `>= 0`; `distanceKm` — скінченне `>= 0`; наявність хоча б одного
    коректного запису.
14. **Помилку в обчисленні виявлять** тести з кількома записами (`severalRecordsAreAggregated`),
    тест незмінності після хибного рядка й, для середнього, `assertEquals(3.5, actual, 0.0001)`
    із допустимою похибкою, а не `==`.
15. **Статичний аналізатор** (SpotBugs) без запуску програми шукає потенційні дефекти в
    байт-коді: неперевірені `null`, незакриті ресурси, небезпечні шаблони тощо.
16. **GitHub Actions** автоматично запускає збірку й тести на кожен push/PR на трьох ОС і
    публікує JAR як артефакт.
17. **Версія й номер збірки.** Версія (`1.0.0`) описує стан продукту й змінюється разом із
    кодом; номер збірки (`42`) визначає запуск CI. Знак `+` у SemVer позначає метадані збірки,
    які не змінюють версію; крапка (`1.0.0.42`) створила б четверте число версії, тобто новий
    реліз.
18. **Issue на дефект** має містити кроки відтворення, очікуваний і фактичний результат.
19. **У розділі про доброчесність** вказують інструмент ШІ, ролі, запити, прийняті
    рекомендації, виправлені помилки, власний внесок і підтвердження розуміння коду.
20. **DevOps** допомагає з Maven, SpotBugs, JAR і Actions та діагностує помилки збірки;
    **Валідатор** складає крайові випадки, перевіряє результати й оформлює дефекти.
21. **Найскладніший для пояснення рядок** — `line.split(";", -1)`: `split` приймає регулярний
    вираз, а другий аргумент змінює поведінку з порожніми хвостовими полями.
