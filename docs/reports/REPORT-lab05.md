## 4. `Repository<T>`

```java
public final class Repository<T> { add(T) · addAll(List<? extends T>) · all() · find(Predicate<? super T>) · size() }
```

- **Параметр типу `T`**: компілятор підставляє `TrainingRecord`, тому типи перевіряються без
  приведень; raw type не використовується, `Object` замість `T` — теж.
- **`all()`** повертає `List.copyOf(...)` — незмінний знімок: зміна знімка кидає
  `UnsupportedOperationException`, а подальші `add` не змінюють уже отриманий знімок.
- **`find(Predicate<? super T>)`**: `? super T` приймає умову над `T` або його супертипом
  (тест передає `Predicate<Number>` для `Repository<Integer>`).
- `add(null)` → `NullPointerException`. Внутрішній список назовні не виходить.

## 5. Модель даних

`TrainingRecord` — `final` клас із `private final` полями й геттерами `date()`, `kind()`, …
Інваріанти (конструктор): `date`, `kind`, `note` не `null`; числа `>= 0`; дистанція скінченна →
`IllegalArgumentException`/`NullPointerException`. `equals`/`hashCode` використовують усі шість
полів (`Double.compare` для дистанції), поля незмінні, тому запис безпечний як ключ. Зв'язок з
основною моделлю: `TrainingRecord.of(Training)` і `toTraining()`.

## 6. `@CsvColumn`

```java
@Retention(RetentionPolicy.RUNTIME) @Target(ElementType.FIELD)
public @interface CsvColumn { String value(); }
```

`RUNTIME` — анотація доступна рефлексії під час виконання (без нього `getAnnotation` повертає
`null`); `FIELD` — лише для полів. Анотація тільки описує контракт, експорт виконує
`CsvExporter`.

| Java-поле | `@CsvColumn` | Колонка у файлі (після сортування за іменем поля) |
| --- | --- | --- |
| `calories` | калорії | 1 |
| `date` | дата | 2 |
| `distanceKm` | дистанція | 3 |
| `durationMinutes` | тривалість | 4 |
| `kind` | вид | 5 |
| `note` | нотатка | 6 |

Порядок стовпців — **сортування Java-імен** (за методичкою): `getDeclaredFields()` не гарантує
порядку, тому без сортування заголовок міг би залежати від JVM.

## 7. Рефлексивний експортер

`CsvExporter` не містить назв предметних класів чи перевірок підтипу (`grep -i training` по
`CsvExporter`, `CsvParser` — порожній). Алгоритм `toCsv(Class<T>, List<? extends T>)`:

1. `annotatedFields`: пройти ланцюжок класів від `type` до `Object`, залишити поля з
   `@CsvColumn` (`getDeclaredFields` — бачить і `private`), відсортувати за `Field::getName`,
   перевірити унікальність назв стовпців.
2. Заголовок: назви з анотацій, екрановані, через кому.
3. Для кожного запису: `trySetAccessible()` (якщо `false` → `DataStorageException`),
   `field.get(record)`, `String.valueOf` (`null` → порожнє поле), екранування.
4. `write` додає створення каталогу, `Files.writeString(..., UTF_8, CREATE, TRUNCATE_EXISTING,
   WRITE)`; `IOException` → `DataStorageException` із `cause`.

Екранування: поле з комою, лапкою, `\n` або `\r` береться в `"…"`, лапка подвоюється. Клас
передається окремо, тому порожній список дає заголовок. Універсальність доведено тестами на
сторонніх класах (`Gadget`, `Child extends Base`, `Nullable`, `Plain`, `Twin`).

## 8. Формат CSV

Кодування UTF-8 без BOM; розділювач полів — кома; кінець рядка при записі — `\n` на всіх ОС (файл
побайтово однаковий; парсер приймає `\n`, `\r\n`, `\r`). Еталонний файл
`src/test/resources/csv/records-sample.csv`:

```text
калорії,дата,дистанція,тривалість,вид,нотатка
520,2026-09-01,7.5,45,RUNNING,Ранкова пробіжка
780,2026-09-03,28.4,90,CYCLING,"Маршрут: парк, річка"
450,2026-09-05,2.0,60,SWIMMING,"Тренер сказав: ""ще круг"""
180,2026-09-07,0.0,50,YOGA,"Розтяжка
дихання"
300,2026-09-09,5.6,70,WALKING,
280,2026-09-09,4.2,30,RUNNING,"інтервали, 6x400 м"
```

Рядок із комою — `"Маршрут: парк, річка"`; з лапками — `"Тренер сказав: ""ще круг"""`; з
перенесенням — запис про йогу займає **два фізичні рядки**. Enum записується іменем константи
(`RUNNING`), число — `Double.toString` (крапка, незалежно від локалі).

## 9. Імпорт і round-trip

Алгоритм (`TrainingCsvStore.load`): `Files.readString(path, UTF_8)` → `CsvParser.parseDocument`
(автомат із чотирма станами `FIELD_START`, `UNQUOTED`, `QUOTED`, `AFTER_QUOTE` розрізняє коми й
переноси всередині лапок і поза ними) → перевірка заголовка (множина стовпців збігається з
`@CsvColumn`; порядок стовпців у файлі не важливий) → `CsvParser.toRecords` (відображення
«стовпець → значення», перевірка кількості полів) → `TrainingRecord.fromColumns` (предметний
розбір типів) → `Repository`.

Доказ round-trip (`roundTripRestoresEqualObjects`): шість записів `Repository` → файл → нове
`Repository`; `assertEquals(original.all(), restored.all())` порівнює **значення всіх полів і
порядок**, зокрема enum, `LocalDate`, `double`, нотатки з комою, лапками й `\n`. Відновлення за
ключем `date + kind`: `2026-09-09 + RUNNING` повертає запис «інтервали, 6x400 м», а не ходьбу тієї
самої дати (`restoredRecordIsFoundByDateAndKind`).

## 16. Відповіді на контрольні питання

1. **Параметр типу** дозволяє одному сховищу працювати з будь-яким типом із перевіркою типів на
   етапі компіляції, без приведень і без `Object`.
2. **Параметризований клас і raw type.** `Repository<TrainingRecord>` перевіряє типи; raw
   `Repository` стирає параметр і вимикає частину перевірок (помилка проявиться лише в runtime).
3. **`Predicate<? super T>`** приймає умову над `T` або супертипом, тому одну загальну умову можна
   використати для багатьох сховищ.
4. **`all()` — незмінний знімок**, щоб зовнішній код не міг змінити внутрішній список і порушити
   інваріанти сховища.
5. **Checked exception** змушує викликача обробити помилку; доречний для очікуваних збоїв
   зовнішнього середовища (файл, формат), як тут `DataStorageException`.
6. **`cause`** зберігає початкову технічну помилку (номер рядка, тип `IOException` тощо), без чого
   діагностика втрачається.
7. **`Path` і `Files`** будують шлях незалежно від ОС і дають операції (створення каталогів,
   читання/запис з кодуванням) замість ручного складання рядків із `\` або `/`.
8. **Кодування задають і при записі, і при читанні**, бо інакше використовується кодування ОС і
   кирилиця може зіпсуватися на іншій машині.
9. **`@Retention(RUNTIME)`** залишає анотацію доступною під час виконання; **`@Target(FIELD)`**
   дозволяє ставити її лише на поля.
10. **Анотація — метадані**, вона не містить виконуваного коду; експорт виконує окремий клас, який
    її читає.
11. **`getDeclaredFields()`** повертає всі поля класу (також `private`), але не успадковані;
    `getFields()` — лише `public`, зокрема успадковані. Тому експортер сам проходить ланцюжок
    предків.
12. **`trySetAccessible()`** повертає `false`, якщо доступ заборонено модулями; це треба
    перевіряти й перетворювати на помилку, а не ігнорувати.
13. **Порядок полів детермінований**, бо JVM не гарантує порядку `getDeclaredFields()`; інакше
    заголовок і файл могли б відрізнятися між запусками.
14. **`split(",")`** не знає лапок: розріже поле `"парк, річка"` і не обробить переноси рядка
    всередині лапок.
15. **Екранування:** поле з комою, лапкою чи переносом береться в `"…"`, а кожна лапка всередині
    подвоюється (`"` → `""`).
16. **Порожній список і `Class<T>`:** стирання типів не залишає інформації про `T` під час
    виконання, а без першого запису клас полів невідомий; тому клас передають окремо.
17. **Експортер універсальний** (будь-який клас з `@CsvColumn`, лише запис), а `fromCsv` /
    `fromColumns` — предметний (знає типи й правила конкретного запису).
18. **Рівні помилок:** модель (`IllegalArgumentException`), формат, значення, файл, рефлексія (усі
    — `DataStorageException`, різні повідомлення й `cause`).
19. **Round-trip** доводить, що «об'єкт → CSV → об'єкт» не втрачає й не змінює даних, зокрема
    спеціальних символів, enum, дат і чисел.
20. **Порожній `catch` приховує причину** (немає файла, хибний формат, права доступу) і повертає
    «нормальний» результат; помилку треба обробити з відомою реакцією або передати з контекстом.

## 17. Висновки

Дані варіанта 2 тепер зберігаються у UTF-8 CSV і відновлюються без втрат, експортер працює з
будь-яким анотованим класом, помилки розрізняються за рівнями й зберігають причину, а звіт
лишається побайтово тим самим. Створений CSV — звичайний текстовий файл, який може бути
вхідним для наступного програмного блоку.
